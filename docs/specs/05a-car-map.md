# 사양 05a: 차량 지도(T1)

계약서 `05-night-plan.md` 2·3·4장의 T1 구현 사양이다. 어긋나면 계약서가 우선이고, 계약서와 다르게 한 점은 아래 '계약서와 다른 점'에 모았다.
목표: **차 안에서 달리는 길의 색이 바뀌는 것을 지도에서 확인한다.** 바탕 타일은 쓰지 않고(OSMF 타일 서버 금지) 서버가 준 도로·시군구 도형만 그린다. 앱 영역 안에서만 그린다(순정 내비 위에 겹치지 않는다).

## 화면

| 상태 | 화면 |
|---|---|
| 주행 중(D·R·N) | 앱 영역 전체가 지도. 내 위치 따라가기(북쪽 위, 확대 14 고정). 위 한 줄 `기록 중` + `· 서울 중구`(지금 시군구). **숫자·버튼·카드·QR·애니메이션 없음, 터치 무시, 그리기 1초 1회 이하.** 기록 멈춤·저장 경고가 있을 때만 같은 줄 끝에 작게 덧붙는다. |
| 정차 중(P) | 가로 약 60% 지도 + 오른쪽 40% 패널(기존 03 요소: 지금 시군구·단계 배지·도감·이웃 카드·게스트 QR). 지도는 끌기·핀치 확대, 버튼 `+` `−` `내 위치` `전국`, 레이어 토글 `도로` `시군구`. 패널은 글자를 75%로 줄이고(03 요소를 다 담으려고) 이웃 카드는 패널 너비가 카드 전체형이 들어갈 만큼이면 전체형이다. |
| 좁은 앱 영역(< 1300dp) | 지도를 위에 두고 패널을 아래로 쌓아 줄인다(이웃 카드 축약형, 높이가 모자라면 낮은 순위 줄부터 접음). |
| 주행 규제(DO) | 지도 버튼·토글 숨김, 지도 터치 무시. DO를 모르면 DO로 본다(fail-closed). |
| `FeatureFlags.drivingMap=false` | 지도 없음. 기존 03·03b 화면 그대로. |

모드 결정은 순수 함수 `mapMode(flag, parkedLayout)`·`mapInteractive(mode, DO)`(`map/MapRules.kt`).

## 레이어(그리는 순서)

1. **시군구 칠**: 단계 1·2·3(통과·방문·숙박)은 앰버 `#F59E0B`의 농도 3단계(알파 0x38·0x70·0xA8), 마지막 방문이 365일을 넘은 곳(`faded`)은 채도를 낮춘 `#C79A4C`. 안 간 인구감소지역(92곳)은 청록 바탕 `#1C323A`, 안 간 일반 지역은 칠하지 않는다. 경계선은 `#2A3544`.
2. **안 간 도로**: `#2A3544` 가는 선(서버 `d` 없음). 등급(`mw`·`pr`·`sc`·`mn`)이 높을수록 굵다.
3. **바랜 도로**: `d.at`이 365일을 넘음(`isFaded`, debug 시계 `now=`를 따른다) `#C79A4C`.
4. **달린 도로**: 그 차량이 인정받은 way `#F59E0B`.
5. **이번 주행 잠정**: `GET /trips/:id/live`의 `isNew=true`(그 차량이 처음 달리는 길)는 밝은 앰버 `#FBBF24`, 가장 굵게. `isNew=false`(다시 달린 길)는 달린 도로 색(바랜 길이 다시 살아난다).
6. **로컬 원시 궤적**: 서버 응답을 기다리지 않는 얇은 선(`#FDE68A`). 위치를 8m 이상 움직일 때만 쌓고 메모리에만 둔다(최대 6,000점, 새 주행 시작 때 비움).
7. **내 위치 마커**: 흰 원, 진행 방위를 알면 화살표.
8. **출처**: 오른쪽 아래 `© OpenStreetMap contributors`.

도로·시군구 레이어는 정차 지도에서 각각 끌 수 있다. 선 굵기·색·바램 판정·시군구 칠 색·칸 선택은 순수 함수(`map/MapLayers.kt`)이고 JVM 테스트가 있다.

## 지도 뷰·데이터 로딩

- `map/NubiMapView`: 커스텀 `View`(Canvas, Web Mercator, 북쪽 위), 새 라이브러리 없음. 도형은 읽을 때 정규화 Mercator(x·y 0~1)로 바꿔 두어 그릴 때 삼각함수를 쓰지 않는다. 화면 밖·1픽셀 미만 way는 건너뛰고 점은 0.8px 미만 간격으로 솎는다. onDraw는 네트워크를 하지 않고 `MapRepository.snapshot`만 읽는다.
- `map/MapRepository`: 뷰포트 변경을 **300ms 디바운스**해 화면 주변(25% 여유)의 모자란 **고정 격자 칸**만 워커 스레드(2개)에서 받는다. 칸 크기는 서버 z별 bbox 상한의 절반 이하(z<9 3°, z<11 1°, z<13 0.25°, 그 위 0.075°). 칸 캐시는 최근 사용 순 80칸, 실패한 칸은 15초 동안 다시 묻지 않는다. 새 칸이 올 때까지는 직전에 다 받았던 묶음을 밑에 깔아 지도가 비지 않는다. 트립 종료 매칭이 끝나면(`onTripSettled`) 캐시를 비우고(달린 길·시군구 단계가 달라졌다) 진행 중 응답은 버린다.
- 서버 z는 화면 확대를 내림해 5~16으로 맞춘다. 전국 보기(`전국`)는 확대 약 8이다.
- 확대 5~17.5, 투영·역투영·핀치 확대 기준점 고정은 `map/MapMath.kt`(JVM 테스트).

## 잠정 색칠(서버)

- `POST /trips/:id/points`의 `onPoints` 훅이 `matching/live.ts`를 깨운다. **앞 가장자리 + 뒤 가장자리 디바운스(30초)**: 한동안 조용했으면 점이 오는 즉시 한 번 돌고(첫 색칠이 빠르다), 그 뒤에는 30초에 한 번만(밀린 점이 있으면) 돈다. 환경 변수 `NUBI_LIVE_INTERVAL_MS`나 `liveIntervalMs` 옵션으로 바꾼다.
- 창: 이미 매칭한 끝(`trip_live.up_to_seq`)에서 10점 겹쳐 다음 점부터 최대 2,000점을 Valhalla `trace_attributes`로 보낸다. 점의 50% 넘게 unmatched면 그 창은 버린다.
- 잠정 인정: 이름 있는 way 중 **커버리지 ≥ 0.5 또는 매칭 길이 ≥ 60m**(확정 0.7·500m보다 느슨). `is_new`는 그 차량(alias 합산)의 `driven_ways`에 없는 way일 때, **첫 인정 순간의 값**을 `trip_live_ways`에 저장한다.
- **`driven_ways`·`visited_regions`·완료율·도감에는 쓰지 않는다.** 확정은 기존 트립 종료 매칭이다. 끝난 트립에는 잠정 매칭을 돌리지 않는다. Valhalla·도로 DB가 없어도 점 업로드는 성공한다(다음 점 업로드 때 다시 시도, 별도 재시도 큐 없음).
- 테이블: `trip_live(trip_id, up_to_seq, updated_at)`, `trip_live_ways(trip_id, way_id, is_new)`(`db/schema-map.ts`).

## API

### `GET /map/base?bbox=minlon,minlat,maxlon,maxlat&z=<정수>&vehicleId=`
```json
{ "z": 14, "truncated": false, "snapshotMonth": "202611", "attribution": "© OpenStreetMap contributors (ODbL)",
  "ways": [ { "id": 26268355, "cls": "pr", "rk": "nm:11110:율곡로", "c": [[126.99723,37.57684],[126.99709,37.57655]],
              "d": { "at": "2026-02-01T00:00:00.000Z", "cov": 0.8 } } ] }
```
- `cls`: `mw`(motorway·trunk)·`pr`(primary)·`sc`(secondary·tertiary)·`mn`(그 밖 이름 있는 길). z<9는 mw, z<11은 mw·pr, z<13은 +sc, 그 위 전부. 이름 없는 way(`unnamed:`)는 항상 뺀다. z<13은 `_link`와 화면에서 1.5px 미만인 짧은 조각도 뺀다.
- bbox 한 변 상한: z<9 6°, z<11 2°, z<13 0.5°, 그 위 0.15°(넘으면 400 `invalid_bbox`). 최대 8,000 way(넘으면 등급 → 긴 것 순으로 남기고 `truncated: true`). z는 0~22 정수(아니면 400 `invalid_z`). 도로 DB가 없으면 503.
- 좌표는 Douglas-Peucker(허용 오차 = z에서 화면 1픽셀, 256px 타일 기준)로 단순화하고 소수 5자리.
- `d`는 `vehicleId`(alias는 정본으로 합침)가 인정받은 way만: `at` 마지막 인정 시각, `cov` 커버리지.

### `GET /map/regions?bbox=&z=&vehicleId=` (계약서에 없는 추가)
`GET /regions/geo`는 bbox 한 변 3° 상한이라 전국 보기를 못 그려서 둔 지도 전용 경로다. 상한 없이 z별로 단순화한 도형을 준다.
```json
{ "z": 6, "snapshotMonth": "202611", "attribution": "…",
  "regions": [ { "code": "11140", "name": "서울 중구", "level": 2, "depop": false, "faded": true, "p": [ [ [[lon,lat],…] ] ] } ] }
```
`p`는 폴리곤 목록(각 폴리곤은 링 목록, 첫 링이 바깥). `faded`는 단계 ≥ 1이고 마지막 방문이 365일을 넘은 곳(T2의 `shared/fade.ts`가 합쳐지면 그 함수로 바꾼다). `depop`은 현행 92곳.

### `GET /trips/:id/live`
```json
{ "status": "ready", "upToSeq": 59,
  "ways": [ { "id": 651229500, "c": [[126.97706,37.57516],…], "isNew": true } ],
  "region": { "code": "11110", "displayName": "서울 종로구", "level": 0, "firstTime": true } }
```
`status`: `idle`(아직 잠정 결과 없음) · `running`(잠정 매칭 진행·예약 중) · `ready`. `region`은 마지막 점의 시군구(지역 DB가 없거나 못 찾으면 없음), `firstTime`은 그 차량 단계 0이었던 곳. 없는 트립은 404.

## 차량 앱 동작

- **업로드 주기**: 주행 중 지도를 켠 경우(`drivingMap && liveColoring`) 업로드 타이머 60초 → **20초**(`TripEngine.uploadIntervalMillis`). 점 100개 기준은 그대로.
- **잠정 폴링**: 기록 중(상태기계 RECORDING)일 때 워커에서 `/trips/:id/live`를 폴링한다. 트립 id는 `Uploader.liveTripId`(서버에 만든 트립·점 전송 성공 시). 간격 20초, 단 한 트립의 처음 4번은 잠정 way가 아직 없는 동안 5초 간격(첫 색칠을 빨리 보이게).
- **상단 한 줄의 지금 시군구**: 잠정 응답의 `region`(마지막 점)이 가장 최신이고, 없으면 정차 때 받아 둔 `/regions/at` 값.
- **FeatureFlags**(`FeatureFlags.kt`, 기본값 계약서 4장): `drivingMap`·`liveColoring`·`voice`·`parkedMenu`·`guest`·`share`·`intro`. T1이 쓰는 것은 앞의 둘이다.
- **debug 시연**: 기존 `nubi-debug://signal?gpx=…` 재생 중에 지도에서 길 색이 바뀐다. debug 빌드에서만 지도 뷰 `contentDescription`에 `지도 way=<그린 way> driven=<달린 way> live=<잠정 way> new=<처음 달린 잠정 way> trail=<궤적 점> roads=on|off regions=on|off region=<시군구 수> z=<확대> follow=on|off`가 들어가 Maestro 단언에 쓴다(release에는 없다). 업로드·잠정 반영 시각은 logcat 태그 `NubiUpload`·`NubiMap`에 `wall=<epoch ms>`로 남는다.

## E2E

기존 flow 3개를 유지하고 단언을 추가했다: 정차 지도(지도 요약·버튼 6개), 주행 중 지도(버튼 없음·궤적이 쌓임·`live=n new=m`으로 잠정 새 길이 들어옴), 정차 레이어 토글·확대·축소·전국·내 위치, 서버 쪽 `/trips/:id/live`·`/map/base` 검증(`scripts/e2e-car.sh`).
바뀐 기존 단언(사양 변경 때문): 주행 중 화면의 보조 문구 `숫자와 지역 카드는 정차(P)하면 보여요`는 지도 화면에 없으므로 `지도 way=…` 단언으로 바꿨다(숫자·카드·QR·길안내가 없다는 단언은 모두 유지).

## 한계

- 바탕 타일이 없어 도로·시군구가 없는 곳은 빈 배경이다(건물·하천·지명 없음). 지명은 시군구 이름뿐이다.
- 잠정 색칠은 점 업로드(20초) → 서버 디바운스(첫 호출은 즉시, 이후 30초) → 차량 폴링(5~20초)을 거치므로 **수 초에서 약 1분 늦다**. 그 사이 지나온 길은 로컬 궤적이 얇은 선으로 보여 준다. 실측(에뮬레이터, 실제 Valhalla, 세종대로 60점 재생, 업로드 20초 간격): 첫 배치는 업로드 직후 0.01초(서버 즉시 실행, 첫 폴링과 겹침), 이후 배치는 업로드 후 23~24초(서버 30초 디바운스 남은 시간 + 폴링 주기). 서버 단독으로는 첫 배치 0.27초, 이후 약 29초.
- 확정 기준(커버리지 0.7·500m)과 잠정 기준(0.5·60m)이 달라, 잠정에서 밝게 칠해졌던 길이 트립 종료 매칭에서 인정되지 않으면 종료 뒤 지도에서 사라진다.
- 한 칸 8,000 way 상한: 도심 z14에서는 작은 골목(`mn`)이 일부 빠질 수 있다(등급 → 긴 것 순). 전국 보기(z8)는 고속도로·국도 조각이 많아 칸당 상한에 걸리면 짧은 조각이 빠진다.
- 패널 글자를 75%로 줄이는 것은 03 요소를 40% 폭에 다 담기 위한 임시 방편이다(시안 03을 지도 레이아웃으로 다시 그리면 없앤다).
- 지도 터치 조작은 에뮬레이터 마우스·Maestro 탭으로만 검증했다(핀치는 JVM 투영 테스트로 대체).
- 폴링·지도 데이터 요청은 인증 없이 `vehicleId`/`tripId`만 쓴다(사양 03 10장의 공개 배포 전 인증 과제 그대로).
