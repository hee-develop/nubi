# 사양 04: 차량 앱 디자인 적용

## 범위
글자뿐이던 차량 앱 화면(`MainActivity`)을 시안 00(브랜드)·03(정차 P)·03b(주행 중)에 맞춘다. 기능·판정 로직·표시 규칙(숫자는 기어 P일 때만)은 그대로다.
시안의 '시안' 배지, 하단 ※ 안내문, 왼쪽 Driving view·상단바(Pleos 시스템 영역 자리표시)는 앱에 넣지 않는다. 앱은 앱 영역(어두운 패널)만 그린다.
색은 `colors.xml`, 치수는 `dimens.xml`(Pleos 원본 px를 에뮬레이터 density 160의 dp·sp로 1:1, 가안), 문구는 `strings.xml`. 숫자는 `tnum`, 폰트는 시스템 폰트. 로고 마크는 `drawable/logo_mark.xml`(`scripts/make-logo-mark.mjs`로 생성).

## 화면별 구성
**기어 D·R·N (03b)**: 가운데 로고 마크, 상태 문구(`기록 중` 등), `숫자와 지역 카드는 정차(P)하면 보여요`. 기록 멈춤·저장 경고·마지막 업로드 줄은 작게 아래에 둔다. 숫자·카드·버튼·QR·애니메이션 없음.
**기어 P (03)**: 정차 화면 레이아웃은 `numbersVisible`이 참일 때(기어 P, 기어 미지원 차량은 기록 중이 아닐 때) 쓴다. 주행 규제가 없는 동안 눌러야 할 것(권한·재시작)이 있으면 기어와 무관하게 이 레이아웃을 쓰되 숫자·카드는 숨긴다.
- 헤더: 로고 + `누비`, 상태 칩(`정차 중 · P`).
- 왼쪽 열: `지금` + 현재 시군구 표시 이름 + 상태 문구, 단계 배지(`안 감 ○○○`/`통과 ●○○`/`방문 ●●○`/`숙박 ●●●`)와 마지막 이벤트, `새 도로`·`전국`, `시군구 n/229`·`인구감소지역 n/92`(강조색 숫자), 처음 지난 곳, 샘플·거리, 마지막 업로드, 경고·권한 카드·재시작 버튼. 현재 시군구를 모르면 제목 자리에 상태 문구(`대기`·`종료됨` 등).
- 왼쪽 아래: 게스트 QR 카드(정적 VectorDrawable, 고정 문자열 QR, `준비 중`, 터치 동작 없음).
- 오른쪽: `안 가 본 이웃` 카드(안 가 본(level 0) 이웃 중 첫 항목. 이웃이 모두 가 본 곳이면 `이웃은 모두 가 봤어요`만 보이고 항목 카드·길안내는 숨김. 이웃 이름, 인구감소지역이면 청록 태그, `관광지`·`축제` 항목 카드 2개, 각 `길안내` 버튼, `자료: 한국관광공사(예시)`, 길안내 결과 한 줄).
- 앱 영역이 좁을 때(< 1300dp. 사용자가 두 앱을 나란히 열어 각 앱에 좁은 영역이 주어진 경우 등): 본문을 세로로 쌓아 왼쪽 열을 너비 전체로 쓰고(고정 660dp 해제), 이웃 카드는 축약형(이웃 이름 + 인구감소 태그 + 길안내 1개, 예시 항목 카드·자료 줄은 숨김)으로 아래에 둔다. 높이가 모자라면 낮은 순위 줄부터 접는다(`foldLines`).
- 주행 규제(DO): 버튼·카드·QR·권한 카드 숨김, 문자열 길이 제한, 등록 실패 시 fail-closed. 1초 1회 갱신.

## 예시·준비 중 요소
- 게스트 QR: `준비 중`. 이미지는 의미 없는 고정 문자열이고 스캔해도 동작하지 않는다.
- 관광지·축제 항목 제목은 이웃과 무관한 고정 문구이고 `예시 항목`·`자료: 한국관광공사(예시)`로 표기한다. 실제 관광 데이터 연동은 없다.
- 길안내는 항목이 아니라 이웃 시군구 중심점(bbox 중심)으로 요청한다. `requestRoute`에는 `NAVI_ROUTE`와 `NAVI_ROUTE_SEARCH`가 모두 필요하다(`NAVI_ROUTE`만으로는 SecurityException, 에뮬레이터 실측).

## 새 API (서버)
- `GET /regions/at?lat=&lon=&vehicleId=` → `{ code, name, displayName, sidoName, level, depop92 }`. 못 찾으면 404, 입력이 잘못되면(빈 값·16진·공백·지수 표기·범위 밖) 400, 지역 DB 없으면 503. `level`은 이 차량의 단계(0~3).
- `GET /regions/neighbors` 항목에 `center: { lat, lon }`(bbox 중심, `nearest` 항목 포함) 추가.
- 차량 앱: 정차(P) 진입 때와 트립 종료(매칭 폴링 종료) 뒤에 마지막 위치로 `/regions/at` → 그 코드로 `/regions/neighbors`. 마지막 위치(`TripStateMachine.lastRaw`)는 채택·기어와 무관한 원시 위치로 P에서도 갱신하고 트립에는 넣지 않으며 메모리에만 둔다. 위치를 모른 채 P로 콜드 스타트하면 첫 위치가 들어올 때 1회 조회한다.
- 워커 스레드에서 조회하고 실패하면 30초 뒤 1회 재시도한다. 실패해도 마지막 성공 값을 유지하되, 새 위치가 마지막 성공 조회 지점에서 2km 이상 멀어지면 조회 전에 옛 값을 비워 화면은 제목 자리에 상태 문구로 돌아간다(옛 시군구를 '지금'으로 두지 않는다). 위치는 로그에 남기지 않는다(`LogMask`).
- 길안내: `NaviLauncher`가 NaviHelper `requestRoute`를 요청만 하고(권한 `pleos.car.permission.NAVI_ROUTE`) 결과를 카드 아래 짧은 문구(`길안내 요청을 보냈어요`/`길안내 연결에 실패했어요`)로만 알린다. 팝업·토스트 없음.

## 완료 기준
1. `pnpm typecheck`, `pnpm server:test`, `cd car && ./gradlew :app:testDebugUnitTest :app:assembleRelease` 통과.
2. `PORT=<포트> pnpm e2e:car`가 재시도 없이 2회 연속 통과(주행 중 숫자·카드·QR·길안내 숨김 단언 포함).
3. 스크린샷으로 기어 D, 기어 P 대기, 트립 종료 후, `서울 중구 방문` 직후 P 화면(이웃 카드 포함)을 확인.
